# volmon · 跨平台音量 / 噪音监控软件

> 开源地址：<https://github.com/hzl790209/volmon> ｜ 许可证：[MIT](./LICENSE) ｜ 参与贡献：[CONTRIBUTING.md](./CONTRIBUTING.md) ｜ 安全漏洞：[SECURITY.md](./SECURITY.md)
>
> **volmon-mac 1.0.3**（macOS 版，2026-09-27 定版；1.0 之后的行为增强，按 1.0.x 递增）—— 当前已打包发布版本

volmon 是一款**跨平台开源**的环境音量 / 噪音监控软件。通过电脑麦克风实时监控周边音量，提供
**Web 实时页面** 与 **命令行终端** 两种可视化形态，支持
**专业设备校准**、**阈值预警**、**声音报警**、**分时段策略**、**触发录音**、
**超量监控日志** 与 **每日报警邮件推送**。

目前提供 **macOS / Windows / Android** 三端：macOS 与 Windows 共用同一套 Python 后端（差异仅在入口与打包），
Android 为原生 Kotlin 实现（复用 dB 算法与 Web 仪表盘思路）。

## 架构
```
麦克风 → AudioEngine(采集+RMS→dB+校准) → AlertManager(阈值/持续) → Storage(SQLite)
                                                              ↓
                                            WebSocket 广播 → Web 页面 / CLI 终端
                                            详细日志 → data/volmon.log（按日切割）
```

- **麦克风权限**：首次运行会弹窗请求，点「好」。若误点了「不允许」，
  到「系统设置 → 隐私与安全性 → 麦克风」里把 volmon-mac 打开。

**终端实时波形**（可选）：
```bash

```

**从源码重新打 DMG**：
```bash
./build_dmg.sh          # 产物 dist/volmon-mac.app + volmon-mac-1.0.3.dmg
```

> 打包要点（改代码时别踩）：`.app` 内部是**只读**的，所以新增的数据文件必须走

> 不能直接用 `__file__` 拼路径——否则打包后要么写不进去、要么破坏签名。

## 使用

> 注意：`main.py` 必须带**子命令**。直接 `python main.py` 只会打印帮助并退出，不会启动。

**最简：一键启动脚本（推荐）**
```bash
# Windows：双击 start.bat，或命令行执行
start.bat
# macOS / Linux / 本沙箱：
./start.sh
```
脚本会自动创建虚拟环境、安装依赖并启动服务。

**`volmon` 命令（macOS/Linux，已安装到 `~/bin`）——一条命令即可启动**
```bash
volmon              # 一键：后端服务没在跑就自动后台拉起 → 就绪后进入终端实时波形
volmon status       # 看服务是否在跑（版本 / 采集设备 / 报警输出）
volmon start        # 只启动后端服务
volmon stop         # 停止后端服务
volmon restart      # 重启后端服务
volmon web          # 浏览器打开实时面板（服务没起会自动起）
volmon cli          # 只进终端波形（服务没起会自动起）
volmon quiet 60     # 60 分钟内超阈值也不发声（监测与记录照常）
volmon quiet --cancel
volmon mail --send  # 立即发送报警日报邮件
```

> 以前不带参数只跑 CLI，**服务没启动时等于什么都没发生**（CLI 连不上后端）。
> 现在会自动探测 `/api/health`，没在跑就 `nohup` 后台拉起并等待就绪，再进入波形。
> Ctrl-C 退出波形后服务仍在后台运行，要停请 `volmon stop`。

**手动（需先装依赖）**
```bash
pip install -r requirements.txt

# 1) 启动后端服务（同时托管 Web 页面 + WebSocket 广播 + 落库）
python main.py serve

# 1b) 无麦克风演示/测试模式（用模拟音量，验证全栈无需真实声卡）
python main.py serve --fake

# 2) 浏览器打开实时面板（默认 http://127.0.0.1:8000）
python main.py web

# 3) 另开一个终端，看命令行实时波形 + 超量横幅
python main.py cli
```

```

纵轴=音量 dB (20~80)   横轴=时间   红色行=预警阈值 70.0 dB
```

- **纵轴** = 音量 dB（自适应刻度，含阈值，最小跨度 30dB）；**横轴** = 时间（左起点 / 中 / 右 `现在`）
- 红色 `-` 行 = 预警阈值；`*` 为采样点，`|` 为纵向连线
- 顶部状态条：报警播放中(静默) / 冷却中(静默) / 超量告警! / 超阈值 / 正常
- 图表尺寸随终端窗口自适应；全 ASCII 字符，任意终端下不错位

### 校准（让软件读数与专业声级计对齐）
1. 用专业噪音仪测得当前环境真实 dB（例如 65.0）。
2. 保持环境稳定，在 Web 校准面板输入 `65.0` 并点「一键校准」；或命令行：
   ```bash
   python main.py calibrate 65.0
   ```
3. 此后软件读数 = 原始值 + 偏移，与专业设备一致。可随时重新校准。

> **关于"未校准时显示负数"**：麦克风算出的是 **dBFS**（满刻度=0，真实声音恒为负，如 -46），
> 直接显示会看到负值。软件已按 `dB SPL ≈ dBFS + 90` 换算成**估算声压级**（界面标注「未校准(估算)」），
> 典型映射：-46→44 dB（安静房间）、-30→60 dB（正常交谈）、-10→80 dB（嘈杂）。
> 90 是通用估计值；**用专业设备「一键校准」后即为真实 dB SPL**。若你的麦克风灵敏度特殊，
> 可调 `ref_spl_offset_db`：`python main.py config set ref_spl_offset_db 95`

### 阈值与设置
- Web 页面「预警设置」面板直接修改并保存（阈值、持续时长、采集/落库频率、输入设备）。
- 或命令行：`python main.py config set threshold_db 70`

### 音量报警（电脑发声 + 自激防护）
- Web 页面「音量报警」面板勾选「开启音量报警」即可：音量持续超阈值后，电脑扬声器播放
  "嘀—嘀—"报警声（默认 10s），提示现场人员。
- 报警声会被本机麦克风拾回，因此**播放期间 + 结束后冷却期（默认共 15s）内，噪声监测整体静默**：
  不写入采样、也不触发噪声超量告警，避免报警声被误记为噪音、造成自激；冷却结束后自动恢复检测。
- 可调参数：`alarm_enabled`（开关）、`alarm_duration_sec`（报警时长，默认 10）、`alarm_cooldown_sec`（冷却秒数，默认 5）。
- 命令行：`python main.py config set alarm_enabled true`
- **听不到声音？** 先用「🔊 试听报警音」按钮（或 `curl http://127.0.0.1:8000/api/alarm/test`）验证扬声器与播放器是否正常。
  注意：报警只在**音量持续超过阈值**时触发（不是开启就响）；且**改动代码后必须重启服务**才会生效。
  另：`serve --fake` 演示模式不发声。

### 报警声从哪一路输出（3.5mm 耳机 / USB 耳机 / 本机扬声器）
- Web「音量报警」面板的**报警声输出设备**下拉里选，改完**立即生效，无需重启**。
- 选完点「🔊 试听报警音」就能确认声音是不是从你想的那一路出来。
- 命令行：`python main.py config set alarm_output_device "HECATE GM400"`（设为空串 = 系统默认输出）。
- 插拔耳机后列表没更新？点下拉下方的「🔄 刷新输出设备列表」。

### 输入设备 / 热插拔
- **改了输入设备会立即生效，不需要重启服务**（2.7.0 起）：在服务广播循环里检测到配置变化后，
  自动停流 → 换设备 → 重启采集流（100ms 内完成）；若新设备打不开会**自动回滚**到原设备继续采集。
- **怎么确认到底在用哪个麦克风？** 「实时音量」面板有一行
  `采集设备：HECATE GM400（索引 0 · 44100Hz）`，显示的是采集流**真正打开**的设备；
  若与你所选的不一致会**红字告警**。也可 `curl http://127.0.0.1:8000/api/status` 查看。
- **插了 USB 声卡/耳机但列表里没有新设备？** 不是权限问题——**PortAudio 在进程内只在启动时枚举一次
  音频设备**，之后插上的设备不会自动出现。点「预警设置 → 🔄 刷新输入设备列表」即可（会中断采集约 1 秒），
  **不需要重启服务**。
- 若读数恒为 -100 dBFS（页面/终端红字提示「麦克风持续静音」），多半是 **PortAudio 默认输入设备**
  指向了虚拟声卡或已拔出的设备。更多排查见下方「输入设备选不对会一直静音」。

### 日志维护（一键清空 / 按时间段清空）
右栏「日志维护（清空）」面板：

- **清空范围**：采样 + 超量告警 / 仅采样记录 / 仅超量告警
- **时间范围**：全部（一键清空）/ 近 1 小时 / 近 24 小时 / 近 7 天 / **自定义起止时间**
- 清空告警后会**同步重写**本地 `data/alerts.csv`，不会出现"库里没了、CSV 里还在"。
- 命令行：
  ```bash
  python main.py clear --all                       # 一键清空全部（会二次确认）
  python main.py clear --hours 24                  # 只清近 24 小时
  python main.py clear --start "2026-09-27 00:00" --end "2026-09-27 12:00"
  python main.py clear --scope alerts --hours 24   # 只清超量告警
  python main.py clear --all --yes                 # 跳过确认
  ```
- 对应接口 `POST /api/logs/clear`，参数 `{"all":true}` / `{"hours":N}` / `{"start_ts":ms,"end_ts":ms}` + `{"scope":"all|samples|alerts"}`。
- 按时间段清空时，**对应日期的归档 CSV 也会同步重写**，不会出现"库里没了、归档 CSV 里还在"。

### 触发录音（把报警时的真实声音存下来）

在页面右栏「**触发录音**」面板打开开关即可。默认**关闭**（涉及录音，请自行确认后开启）。

**为什么不会漏掉开头？** 声音往往很短（敲门、喊叫、器物掉落），而从"发声 → 算 dB → 判超阈值 →
判持续时长 → 打开文件准备写入"这条链路有延迟，**等报警了才开始录必然缺开头**。
所以这里用的是**常驻环形缓冲 + 前置录音**：

```
时间轴 ──────────────────────────────────────────────►
声音:            ▁▂▅█▇▅▂▁              （只有 0.3 秒）
                 ↑
缓冲:  [一直在滚动保留最近 5 秒……][触发点][继续录 5 秒……]
        └── 前置（内存里倒出来）──┘        └── 后置 ──┘
文件:  ┕━━━━━━━━━━ 完整一段，开头不缺 ━━━━━━━━━━┙
```

- 采集流一直在跑，最近若干秒的原始音频**始终留在内存**（约 1.8 MB，开销可忽略）
- 触发瞬间直接把"触发前"那段取出来，再接着录"触发后"，拼成完整一段 WAV
- **触发链路再慢、声音再短，开头都不会缺**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `rec_enabled` | false | 总开关（默认关闭） |
| `rec_trigger` | alert | `alert`=正式报警（推荐，误录最少）；`over`=刚超阈值（最早但可能较多） |
| `rec_pre_sec` / `rec_post_sec` | 5 / 5 | 触发前保留 / 触发后继续录的秒数 |
| `rec_keep_days` / `rec_max_files` / `rec_max_mb` | 30 / 500 / 2048 | 保留天数 / 最多文件数 / 总大小上限，超出自动删最旧的 |
| `rec_dir` | data/recordings | 存放目录（内部按日分子目录） |
| `rec_cut_on_alarm` | **true** | 开启声音报警时，报警一触发就把正在录的这段**截断在触发瞬间**（仅留触发前音频，绝不录报警声，见下） |

- **回放**：超量告警表格新增「录音」列，点 **▶ 播放** 即可试听或下载；
  `alerts` 表与 CSV 也增加了 `audio_file` 列
- **命令行**：`python main.py rec`（看状态）/`--list`（列文件）/`--prune`（立即清理）
#### 开启声音报警时：报警触发即截断（`rec_cut_on_alarm`，默认开）

报警声是**本机扬声器放出去的**，会被同一台电脑的麦克风原样拾回——录进 WAV 就是一段刺耳的
"嘀嘀"声，把真实环境音盖掉。软件**没法把两个混在一起的声音再分开**，所以采取**最干脆也最可靠**
的办法：**报警声是从触发点才响起来的，那报警一触发，立刻把录音"定格"在触发瞬间，触发之后的声音一个字节都不写**。

```
报警触发瞬间
   │
   ▼
──┴────────── 前置段（触发前，真实环境音）────────────┐
   │                                              ┝━ 这一份写进 WAV（完整）
麦克风 ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁░░░░░░░░
   └ 触发点之后的报警声（本机外放）── 直接丢弃，永不写入
```

- **前置段照留**：触发前那段环形缓冲里的真实环境声照常保留、写入 WAV（报警声那时还没响，本来就是干净的）
- **触发点之后一刀切**：报警一旦触发，所有"正在录"的任务立刻标记为"已截断"，只等把已有前置段写盘即收工，
  **报警声（以及之后其它声音）一律不进文件**
- 面板上会显示 **✂ 报警触发即截断**；保存的录音会标注"报警触发·已截断（仅含触发前音频）"
- 这是**与"跳过污染窗口"不同的更可靠方案**：不再计算"报警响多久"去雕刻录音，而是直接从触发点切断，
  因此无论报警时长、冷却怎么设，报警声**物理上不可能**出现在录音里

- **已知限制**：
  1. 服务刚启动的头几秒缓冲还在填充，这时的录音"前置段"会短一些，运行片刻后即稳定
  2. 开着声音报警时，录音会在触发点结束（不含报警后声音）——这是**预期行为**，目的是保护录音不被报警声污染
  3. 从根本上避免串扰，还是建议**报警输出接耳机**（或外接音箱远离麦克风），
     这样触发点之后也能录到连续完整的真实声音
  4. 演示模式（`--fake`）录到的是合成噪声，不是真实声音

### 每日报警邮件
右栏「每日报警邮件」面板：填好 SMTP 与收件人后，软件**每天自动把前一天的报警日志发一封邮件**。

- **邮件内容**：超量次数 / 峰值 dB 及发生时刻 / 平均峰值 / 累计超标时长 / 最长一次 /
  时段分布（白天·晚间）/ 阈值分布 / 开启声音报警的次数 / 明细表（最多 50 条）；
  正文有 HTML 与纯文本两种，可选**附带当天告警 CSV 附件**。
- **发送时机**：每天 `mail_send_time`（默认 **09:00**）自动发一次，报表范围默认**昨天全天**
  （可改成"今天 00:00 起"）。服务当天启动晚了会**补发一次**，同一天不会重复发；
  发送失败当天最多重试 3 次。
- **配置（页面填写即可）**：

  | 项 | 说明 |
  |----|------|
  | 每天自动发送 | 总开关 |
  | SMTP 服务器 / 端口 / 加密 | 内置 QQ / 163 / Gmail / Outlook / 腾讯企业邮 **一键填入** |
  | 发件邮箱账号 | 如 `123456@qq.com` |
  | 授权码 | **不是登录密码**，需在邮箱设置里开启 SMTP 后生成 |
  | 收件人 | 多个用英文逗号分隔；留空则发给自己 |
  | 报表范围 / 发送时间 | 昨天全天（默认）/ 今天起；默认 09:00 |
  | 附带 CSV / 无告警时不发 | 是否带附件；无告警时是否跳过（默认仍发"平安信"） |

- **先预览再发**：点「预览报表」会在新窗口打开邮件正文；确认无误再点「立即发送测试邮件」。
- 命令行：
  ```bash
  python main.py mail                                  # 查看当前邮件配置与最近发送结果
  python main.py mail --preview                        # 预览报表（不发送）
  python main.py mail --send                           # 立即发送昨天日报
  python main.py mail --send --day 2026-09-26          # 补发指定日期
  python main.py config set mail_to you@example.com
  ```
- 接口：`GET /api/mail`、`POST /api/mail/send`（`{"dry_run":true}` 预览 / `{"day":"..."}` 补发）。
- **安全**：密码请填授权码；接口返回给页面的密码一律脱敏为 `●●●●●●`。

### 日志按日切割与保留（默认保留 30 天）
右栏「日志文件（按日切割）」面板可看到每类日志的**今天文件**与**各天归档**（含大小），
并可调整「按日切割」开关与「保留天数」（0 = 永不删除）。命名规则：

| 日志 | 当前文件（今天） | 归档文件 |
|------|------------------|----------|
| 运行日志 | `data/volmon.log` | `data/volmon_2026-09-26.log` |
| 超量告警 CSV | `data/alerts.csv` | `data/alerts_2026-09-26.csv` |
| 重启日志 | `data/restart.log` | `data/restart_2026-09-26.log` |
| 采样数据 | `data/volmon.db`（**单库不切割**，用「日志维护」清理） | — |

- 跨天后的**第一次写日志/写告警**自动切割；服务启动时也会把"昨天遗留的当前文件"归位，
  保证当前文件里只有今天的内容
- 超过 `log_keep_days`（默认 30）天的归档自动删除
- 命令行：
  ```bash
  python main.py logs --files              # 查看日志文件清单（当前 + 归档）
  python main.py logs --rotate             # 立刻切割一次（只在真跨日时动）
  python main.py logs --rotate --force     # 强制归档当前文件
  python main.py config set log_keep_days 60
  ```
- 对应接口 `GET /api/logs/files`、`POST /api/logs/rotate`（`{"force":true}`）

### 超量告警日志里记录的策略信息
每条超量告警都会记下**当时的策略**，便于事后追溯"那次报警用的是哪套阈值、报警开没开"：

- 新增列：`period`（白天/晚间）、`schedule_applied`（是否分时段）、`alarm_enabled`（是否启用声音报警）、
  `alarm_duration_s`、`alarm_cooldown_s`
- Web「超量告警日志」表格新增「时段/策略」「声音报警」两列
- 本地 `data/alerts.csv` 同样包含这些列（Excel 可直接看）
- 文本日志示例：`超量片段结束 | 峰值=62.5 dB | 阈值=55.0 | 持续=4.0 s | 策略=晚间（分时段） | 声音报警=开 10s`

### 分时段策略（白天 / 晚间两套阈值与报警策略）
白天和晚间用不同的管理策略。Web「分时段策略（白天 / 晚间）」面板：

- 勾选**启用分时段策略**（默认关闭，关闭时沿用全局阈值与报警设置）。
- 两个时段**各自设置起止时刻**，**支持跨零点**（例如晚间 `22:00 → 07:00`）。
- 每个时段可独立设置：

  | 项目 | 说明 |
  |------|------|
  | 阈值 (dB) | 该时段超多少 dB 算超量 |
  | 持续 (秒) | 需连续超多久才判定为告警（避免瞬时误报） |
  | 报警开关 | 该时段超阈值时是否**发声报警** |
  | 报警时长 / 冷却 | 该时段的报警声持续秒数与结束后冷却秒数 |

- 改动**立即生效**，无需保存或重启。面板底部实时显示：
  `当前：白天（分时段已启用）　生效阈值 70 dB · 持续 3s · 报警 关　|　距切换约 7 小时 30 分`
- **典型用法**：白天 `70 dB` 只记录不报警（白天本来就有各种声响），晚间 `55 dB` 且开启报警。
- 两个时段若没覆盖满 24 小时，会黄字提示「有 N 分钟空档 / N 分钟重叠」；空档按白天策略执行。
- 命令行：
  ```bash
  python main.py schedule                          # 查看当前时段与生效策略
  python main.py schedule night_threshold_db 55    # 设置晚间阈值
  python main.py schedule night_start 22:00        # 设置晚间开始时刻
  python main.py schedule day_alarm_enabled false  # 白天不发声报警
  ```
  可选键：`schedule_enabled`、`day_start/day_end`、`night_start/night_end`、
  `day_threshold_db/night_threshold_db`、`day_sustain_sec/night_sustain_sec`、
  `day_alarm_enabled/night_alarm_enabled`、`day_alarm_duration_sec/night_alarm_duration_sec`、
  `day_alarm_cooldown_sec/night_alarm_cooldown_sec`。
- 分时段只覆盖阈值与报警策略；报警声**输出设备**、报警静音时段仍是全局的。

### 报警静音时段（人要离开一段时间时用）
布置好环境后你要走开，脚步声/说话声会不停触发报警——用这个功能：设一段时间后，
**该时段内超阈值也不发声**，到期自动恢复，也可随时手动取消。

- Web「报警静音时段」面板：**静音 30 分钟 / 1 小时 / 2 小时** 快捷按钮，或填自定义分钟数，
  另有「▶ 取消静音」立即恢复发声。面板实时显示剩余倒计时。
- 命令行：
  ```bash
  python main.py quiet 60        # 静音 60 分钟
  python main.py quiet           # 查看当前静音状态与剩余时间
  python main.py quiet --cancel  # 取消静音，立即恢复发声
  ```
- **与"报警后自激静默"的区别（重要）**：
  | 场景 | 发声 | 采样落库 | 超量告警记录 |
  |------|------|---------|-------------|
  | 报警播放中 + 冷却期 | 正在响 | ❌ 暂停 | ❌ 暂停 |
  | **报警静音时段** | ❌ 不响 | ✅ 照常 | ✅ 照常 |

  即：静音时段**只是不响，不会丢数据**，你回来后仍能在超量日志里查到期间的超量事件。
- 配置 `quiet_until_ms`（截止时刻 epoch 毫秒，0 = 未静音）；「恢复默认设置」会一并清除静音。

### 服务控制（Web 页面「服务控制」面板）
- **↺ 恢复默认设置**：把阈值/校准偏移/报警/输入设备等全部还原为出厂默认值。
- **⟳ 重启服务**：派生接替进程并以相同参数重启（用于更换输入设备或改代码后生效），约 2 秒后刷新页面。

### 输入设备选不对会一直静音
- 若读数恒为 -100 dBFS（页面/终端会红字提示「麦克风持续静音」），多半是 **PortAudio 默认输入设备**指向了
  虚拟声卡或已拔出的设备（如 iPhone continuity 麦克风），**并非麦克风权限问题**。
- 处理：在「预警设置 → 输入设备」下拉里换成有信号的设备（可用 `python -c "import sounddevice as sd; print(sd.query_devices())"` 查看），
  保存后点「⟳ 重启服务」生效。

`data/config.json`（自动生成）：
| 键 | 默认 | 说明 |
|----|------|------|
| threshold_db | 70 | 预警阈值（校准后 dB） |
| sustain_sec | 3 | 持续超过多久才触发告警 |
| sample_interval_ms | 100 | 实时广播间隔 |
| log_interval_ms | 1000 | 采样落库频率（后台详细日志采样率） |
| calib_offset_db | 0 | 校准偏移 |
| device | default | 输入设备 |
| alarm_enabled | false | 是否开启音量报警（电脑发声） |
| alarm_duration_sec | 10 | 单次报警声持续秒数 |
| alarm_cooldown_sec | 5 | 报警结束后冷却秒数（期间仍静默） |
| alarm_output_device | "" | 报警声输出设备名（空=系统默认输出） |
| quiet_until_ms | 0 | 报警静音截止时刻（epoch ms，0=未静音） |
| db_path / log_path | data/... | 数据库 / 文本日志路径 |
| log_rotate_daily | true | 运行日志与告警 CSV 是否按日切割 |
| log_keep_days | 30 | 归档文件保留天数（0 = 永不删除） |
| mail_enabled | false | 是否每天自动发送报警日报邮件 |
| mail_host / mail_port | smtp.qq.com / 465 | SMTP 服务器与端口（587 配 mail_starttls） |
| mail_user / mail_password | "" | 发件邮箱与**授权码**（非登录密码） |
| mail_to | "" | 收件人，多个用逗号分隔（留空发给自己） |
| mail_send_time / mail_day_offset | 09:00 / 1 | 每天发送时刻 / 报表范围（1=昨天，0=今天） |
| mail_attach_csv / mail_skip_if_empty | true / false | 带 CSV 附件 / 无告警时跳过 |
| rec_enabled | false | 是否录制触发报警时的真实声音（默认关闭） |
| rec_trigger | alert | alert=正式报警时录 / over=刚超阈值时录 |
| rec_pre_sec / rec_post_sec | 5 / 5 | 触发前保留 / 触发后继续录的秒数（前置由环形缓冲提供） |
| rec_keep_days / rec_max_files / rec_max_mb | 30 / 500 / 2048 | 录音保留天数 / 文件数上限 / 总大小上限 MB |

## 数据
- `data/volmon.db`：采样表（samples）+ 超量告警表（alerts）。**单库，不按日切割**。
- `data/volmon.log`：启动、配置变更、校准、超量片段结束等详细事件日志（按日切割）。
- `data/alerts.csv`：超量告警 CSV，按日切割为 `alerts_YYYY-MM-DD.csv`。

## 说明
- 读数经校准后接近真实声压级；未校准时为相对值，仅供趋势参考。
- 仅保存数值，不录制/上传任何音频内容，保护隐私。
- 需在系统/浏览器中授权麦克风权限。
- **读数恒为一条直线 / 显示 -100 dBFS？** 这通常是**麦克风未授权**（macOS 会允许打开音频流但送进全零数据）。
  页面与终端会显示红色告警「麦克风持续静音」。处理：系统设置 → 隐私与安全性 → 麦克风，
  给运行服务的终端（Terminal/iTerm）开启权限，然后用**该终端**重启服务
  （`volmon serve`）。**恢复读数后务必重新校准**——在静音状态下做的校准结果无效。
